# Worker 0.44.0：设置、账号与用户状态闭环

## 范围

接续已部署的 0.43.0（提交 `3d8d69495`、Worker version `d81b24e1-faf7-4c34-bcc4-33481e563213`）。0.43.0 线上完成 37 项检查；一次临时、禁用且未分组的测试账号完成调度切换与审计查询后已删除。该版本已恢复用户确认的原管理操作审计 `/admin/audit-logs`。

本批补齐原设置剩余可执行消费者，并以真实 D1 / Durable Objects / workerd 检查跨层行为：

- Codex CLI 四项规则作用于启用限制的 OAuth 账号，依据原始入站请求校验，覆盖文字与图片出口。仅更新 gateway 设置不再被误判为空；策略拒绝不再使健康账号冷却。
- 独立未分组目录、官方窗口配额阈值、低上游费率优先及 OAuth 调度参考倍率。未分组 Key 不继承私有分组权限，模型须显式授权定价；调度参考倍率不改变实际收费。复合分组的管理面与财务 DO 鉴权现保持一致。
- 原风险控制页面、配置 CAS、多 Key 检测/冻结、关键词/模型/分组规则、抽样、同步阻断、异步队列、哈希缓存、通知与保留策略。异步内容加密保存 R2，Queue 仅传任务标识；自动封禁使用独立耐久命令与用户 DO 权威状态，不能直接修改 D1 财务状态。解封保留旧会话失效，管理员重新禁用后风控不得解封。
- Grok 原生平台、三项默认模型/跨客户端映射/出口设置，显式模型与 URL 配置优先；未知模型不绕过目录权限。Antigravity 的 project/OAuth Bearer 执行、原生目录同步、测试、身份提示与版本设置，以及 Gemini、Chat、Responses、Anthropic 文本协议适配。
- Gemini/Antigravity 流的结束标志后可能仍有用量帧；读取到流结束再按真实用量结算，避免按预留金额多收费。错误空响应不收费，截断不报告完成，超输出限制与余额不足在预留前拒绝。
- Cron 派发 32 个独立维护任务，单任务失败由队列恢复；观测孤儿扫描持久化游标，图片 R2/S3 对象分批续删，避免完整大页超过调用预算。注册赠送订阅保持原子 D1 权益与持久同步意图，后台分批恢复，首次使用按已有路径配置 DO。

## 明确的能力边界

- Worker 不能运行原项目的本地插件二进制；用户尚未提供外部 Go/插件运行服务。保留真实菜单配置，不将菜单可见误报为插件可执行。
- 全量备份包含财务 DO 等状态，不能以部分 D1/R2 导出替代完整恢复。原项目的外部备份执行环境仍需独立接入；当前接口明确返回能力限制。
- Grok/Antigravity 支持导入已获取的 OAuth access token、替换和模型调用；原外部授权/refresh 流程尚未迁移，界面明确使用导入入口。计数、压缩、平台内置工具等缺少实际执行器的跨协议操作明确拒绝，不能伪造成功。
- CCH 是原 Go 项目已废弃的签名开关；保留禁用说明。Workers 无法提供宿主机 CPU/内存指标；不将请求指标伪装成主机指标。
- 官方模型可用性受实际账号额度与上游状态影响。本批本地端到端测试使用受控上游，不能替代用户账号的真实可用性证明。
